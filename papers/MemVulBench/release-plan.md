# MemVulBench 公开发布方案

状态：待实施。本文以 `data/measure/admission/2026-09-18.json` 为准，发布范围为 20 个准入测试单元及 292 个经核验的独立漏洞指纹；arrow 纳入，librawspeed 不纳入本版发布集合。

## 1. 冻结可引用版本

- 将准入决定、修正后的 `evidence/rereplay_fingerprint_ledger.json`、逐项目配置、字段说明、图表源数据及分析代码固定在同一版本标签。记录源仓库提交、上游源码提交、最终镜像和二进制哈希。
- 为每个指纹建立指向测试单元、触发输入、持久首错日志、最终镜像及人工裁决记录的机器可读索引。不得以临时 `/tmp` 路径作为公开定位方式。
- 将历史测试单元和旧版阅读包单列为过程归档，避免与本版 20 个准入单元混合计数。

## 2. 分层归档

- **软件与元数据**：发布原创代码、目录、可再分发的测量元数据、证据索引、配置样例、图表与说明文档，建立公开版本控制仓库，并为冻结版本取得持久标识。当前仓库的 `data/measure/`、`targets/` 被忽略，打包时需按审定清单显式选入所需材料。
- **单元数据**：20 个测试单元分别归档最终聚合镜像、纳入计数的 PoC、最终入口原始日志、运行配置及 SHA-256 清单，并与软件版本和上游提交双向关联。现有 20 个最终镜像合计约 66.56 GB，单个约 1.82–6.52 GB；不把整个约 175 GB 的 `targets/` 历史目录作为本版交付包。
- [Zenodo](https://help.zenodo.org/docs/deposit/manage-files/) 当前单条记录默认支持至多 50 GB、100 个文件；逐单元建记录可容纳现有镜像规模。镜像不宜作为 [GitHub Release](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases) 资产直接上传，其单文件限制为小于 2 GiB。

## 3. 发布前核查

- 逐件核对上游源码、依赖、ARVO 衍生材料及 PoC 的许可、出处和披露状态；为原创代码确定许可。不能合法再分发的工件仅提供原始来源、获取或重建说明、校验值，并说明复验限制。
- 检查工件中是否含凭据、本机绝对路径、个人信息或尚不宜公开的输入；保留必要的安全披露记录。
- 核对归档清单中的路径和哈希，测试匿名读者能否下载并定位 20 个单元及对应证据。涉及镜像加载、编译和 PoC 回放的验收仍由操作员按仓库规则逐项执行和记录。

## 4. 审稿与正式公开

- 审稿阶段向编辑和审稿人提供与投稿版本一致、可访问的受控归档及清单。
- 正式公开后，将软件版本地址、各单元数据归档标识、许可与访问限制填入论文的数据与代码可用性声明，并使归档页指回论文和对应软件版本。
- 在真实地址和持久标识建立前，论文只陈述发布计划，不声称材料已公开。
