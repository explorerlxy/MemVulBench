# 搬运方法论（定稿）

如何把 N 个历史内存漏洞放进同一个二进制，并且能证明它们还是原来那些漏洞。

本文取代 [design.md](design.md) 原 D3 的"修复回退"。回退已被实测否定，不再使用。

---

## 1. 被实测否定的东西

assimp 端到端试点（2026-09-08，`assimp_fuzzer`，基线 `3c253ca3`）：

| 环节 | 结果 |
|---|---|
| 修复补丁回退到基线 | 12/12 干净应用 |
| 回退后 PoC 真正复现 | **3/14（21%）** |
| 同一基线上天然潜伏（不打任何补丁） | **6/6（100%）** |

第一行和第二行的落差是结论：**补丁能否应用完全不能预测漏洞能否重现。**

原因是漏洞不是补丁的逆运算。漏洞是某个文件在某一时刻的**整体形态**——它依赖当时的
缓冲区声明方式、当时还没被重构掉的调用点、当时的校验顺序。`git revert <fix>` 只把
其中一行改回去，产出的是一个历史上从未存在过的混合体。这正是 Magma 沉默漏洞的机制，
而且证明了它不是"手工移植做得不够仔细"的问题——机械回退同样失效。

**推论：任何产生"历史上不存在的文件"的操作都不可用。**

## 2. 唯一构建原语：pin

```
pin(F, C)  ≡  文件 F 取上游 commit C 的 blob
```

一个切片 = 基线 commit `B` + 一张 pin 表 `{F₁↦C₁, …, Fₙ↦Cₙ}`。
未被 pin 的文件全部来自 `B`。

这一个原语吞掉了此前所有路线分歧：

| 原路线 | 在 pin 语言里是什么 |
|---|---|
| 考古（找天然共存的快照） | pin 表为空的特例 |
| 合成（把漏洞搬进来） | 对认领文件 pin 到窗口内某 commit |
| 修复回退 | **不再存在**——它是唯一会生成非上游文件的操作 |

### 保真不变式

> 切片中每一个参与编译的源文件，都逐字节等于某个上游 commit 的 blob；
> manifest 记录每个文件对应哪个 commit。

可机械复验：对每个文件比对 `git cat-file blob <C>:<F>` 的 sha256。
Magma 给不出这条保证——它的每个漏洞体都是手写移植代码。这是 MemVulBench 相对现有
benchmark 最硬的差异点，也是全部设计取舍的锚点。

**唯一允许的例外见 §4.3（函数级逃生舱），且必须单独标记。**

## 3. 认领集与扩张阶梯

漏洞 i 的**认领集** `claim(i)` = 为了让它复现而必须 pin 的文件集合。

初值 = `fix_commit_i` 改动的源文件。assimp 实测：34 个漏洞中 **28 个的修复只改一个
源文件**，33 个改 ≤2 个。漏洞在代码里的占地面积极小，这是整套方法成立的物质基础。

初值不够时按阶梯扩张，扩张的触发条件决定扩张的方向：

| 层 | 范围 | 触发 |
|---|---|---|
| E0 | fix 改动的源文件 | 初值 |
| E1 | + 被 pin 文件所含、且在 `[Cᵢ, B]` 间变更过的同目录头文件 | 编译报错，错误符号指明缺谁 |
| E2 | 崩溃点所在目录整体 | 编译通过但 PoC 不复现 |
| E3 | E2 + 沿 include 图传递闭包中变更过的文件 | 仍不复现 |
| E4 | 整棵树 pin 到 `Cᵢ` | 兜底 |

E4 等价于 ARVO 原始镜像，**必然成功**——所以每个漏洞都存在可行 scope，搜索一定终止。
代价是 scope 越大越容易与别人冲突，E4 意味着密度退化为 1。

扩张后要重算冲突图（§5），因为 `claim` 变大可能制造新的边。整个求解因此是迭代的。

### 三种失败的区分

- **编译不过**：边界切断了耦合。错误可定位，机械扩张。
- **编译过、PoC 不崩**：漏洞依赖的上下文在 scope 之外。按目录扩张。
- **编译过、崩了但指纹不对**：可能是撞上了别的漏洞。不扩张，转人工，多半拒收。

第三类的占比是需要报出来的数字。

## 4. 开关与负对照

### 4.1 开关就是换 pin

每个漏洞有两个 pin 目标：

```
ON   →  vul-pin：窗口 [introᵢ, fixᵢ) 内的某个 commit
OFF  →  fix-pin：同一文件打上 fixᵢ 之后的形态
```

两边都是真实上游文件。于是：

- **负对照免费**。不需要单独维护一棵干净树、单独构建一次。
- **同一棵源码树产出两种二进制**。全开 = 高密度评测目标；单开一个 = 隔离目标。
  两者之差就是漏洞间干扰量——从一个需要担心的假设变成一个可测量的量。
- **漏洞集合可裁剪**。只要 UAF、只要空间越界、只要某个难度档，重新 configure 即可。

落地形式是 configure 阶段选装文件，`-DMEMVUL_BUG_ASM_007=ON|OFF`。
**源码里不需要任何 `#ifdef`**，也就不需要人工把两个版本交织起来。

### 4.2 vul-pin 取哪个 commit

窗口内任一 commit 都能开出漏洞，选择标准是两条互相冲突的诉求：

1. 离 `B` 越近，拼装跨度越小、编译越可能通过；
2. 落在 `fixᵢ^` 上，则 `fixᵢ` 按定义必然能干净应用，开关一定关得掉。

规则：**优先取窗口内时间上离 `B` 最近的 commit；若在该点上 `fixᵢ` 无法应用（关不掉），
退回 `fixᵢ^`。** 两步都是机械可判定的，没有人工判断。

### 4.3 共用 pin 与函数级逃生舱

两个漏洞认领同一文件且窗口**相交**时，它们共用一个 pin，一起进来（这就是"子系统内考古"）。
此时关掉其中一个 = 把它自己的 fix 打到共用 pin 上。这个方向天生可靠：补丁本来就是照着
这份上下文写的（如 assimp `MD5Parser.cpp` 的两个漏洞修复只差 4 天）。打不上就把两者声明为
**一个不可分的开关单元**，明写在 `bug.yaml` 里，不藏。

窗口**不相交**时是真冲突，默认走 §5 分片。仅在此处启用逃生舱：

> **函数级 pin（tier-2）**：在 pin 到 `C_a` 的文件里，把某个函数体整段替换为 `C_b` 上
> 该函数的逐字节原文。

代价必须写清楚：文件整体不再等于任何上游 blob，保真不变式弱化为"**函数体**逐字节等于上游"。
这类漏洞在 `bug.yaml` 里标 `fidelity: function`，在切片摘要里单独计数，
纯度敏感的使用者可以整体排除。实现依赖 clang AST 抽取函数区间，不做文本启发式。

## 5. 冲突与切片构造

```
冲突图 G：顶点 = 漏洞
边 (i,j)  ⟺  claim(i) ∩ claim(j) ≠ ∅  且  window(i) ∩ window(j) = ∅
```

窗口相交的共认领漏洞先合并为共用 pin（§4.3），不产生边。剩下的解**最大独立集**——
图很小，精确求解即可。落选的漏洞进入下一个切片。

assimp 实测的冲突结构（34 个漏洞）：

| | |
|---|---:|
| 被一个以上漏洞碰过的文件 | 10 |
| 与任何其他漏洞零文件重叠的漏洞 | 13 |
| 冲突组内可兼容子集之和 | 14 |
| **单切片上界估计** | **≈26** |

对照：Magma 单目标最多 22 个漏洞（poppler），且全库只有 32.6% 可观测。

### 选片的第三个一等条件：模块化程度

此前已知两条（漏洞数量、开发节奏），实测暴露了第三条，而且它可能最关键：

| 项目 | 崩溃点分布 |
|---|---|
| assimp | 19/34 的修复完全落在单个 `code/AssetLib/<格式>/` 内，插件式架构，导入器互不耦合 |
| harfbuzz | 55 个崩溃点几乎全在扁平的 `src/` 下 |
| matio | 24/29 在 `src/` 下 |

**冲突率由架构决定。** 插件式 / 多格式解析器类项目（assimp、ImageMagick、ffmpeg、
poppler 的各 backend）天然低冲突；单体库（harfbuzz、matio、zlib）高冲突，密度上限低。
选片必须把这条写进打分函数。

## 6. 拼装预算：自己把代价报出来

拼装出来的树是历史上不存在的程序。这个质疑躲不掉，处理方式是**量化、公布、设上限**：

| 字段 | 含义 |
|---|---|
| `mosaic_ratio` | 被 pin 的源文件数 / 参与编译的源文件数 |
| `temporal_spread` | `max(Cᵢ) − min(Cᵢ)` |
| `pin_direction` | 每个 pin 记 `backward`（`Cᵢ < B`）或 `forward`（`Cᵢ > B`），分别统计 |
| `purity` | `pure`（零 pin，纯考古快照）/ `mosaic` |

"500 个文件里 pin 了 3 个、跨度 6 个月"是可辩护的；"pin 了 40 个、跨度 4 年"不是。
具体阈值等 sweep 出了真实分布再定，先记为待定。

`forward` pin（漏洞引入晚于基线，把较新文件装进较老的树）**允许**，机制上与 `backward`
完全对称、同样满足保真不变式，但会推高 `temporal_spread`，所以分开统计、在 manifest
里标方向。`purity: pure` 档天然不含任何 pin，是给最保守口径的使用者的。

### 三条硬约束

- **harness 文件永不 pin**。否则切片之间不可比。harness 自身的漏洞直接排除
  （assimp 的 `379418968` 即属此类）。
- **`test/` 不参与**。
- **共享基础设施上的漏洞单独成片**。assimp 的 `code/Common`（6 个）与 `include/assimp`
  （2 个）冲突风险最高，不与导入器漏洞混片。

## 7. 前提：存活窗口必须实测

整套方法依赖每个漏洞的精确窗口 `[introᵢ, fixᵢ)`。

SZZ 估计不能用：在 assimp 上它把 12 个漏洞预测为基线上存在，实测只有 6 个，2 倍误差。

### 操作定义

> `window(i)` = PoCᵢ 在**未经改动的上游树**上以指纹 `signature(i)` 开火的、
> 以 `fixᵢ^` 结尾的极大连续 commit 区间。

这是"可观测性窗口"而非"缺陷存在窗口"，二者不必相等——采用前者，因为它正是评测关心的东西，
而且它是纯上游属性，不依赖我们的任何构造。区间不连续（漏洞被临时遮蔽）本身是要记录的数据。

### 成本比想象低一个量级

关键在于**一次构建服务全部 PoC**：在 commit C 上构建一次，把全部 PoC 一起回放（assimp
实测 26 个 PoC 共 2 秒），直接得到"C 上谁活着"的整个向量。所以这是**对提交历史扫一遍，
所有漏洞的窗口同时被二分**，不是每漏洞 bisect 一遍。

assimp 2021–2025 区间 1753 个 commit：先按月取 ~30 个探针点建立粗窗口，再只对边界不清的
做几轮细化，几十次构建即可收敛。

副产品可能比 benchmark 本身更有引用价值：**数千个真实 OSS-Fuzz 内存漏洞的实测存活区间**。

## 8. 准入闸门

漏洞 i 进入切片 S 当且仅当全部通过：

| # | 闸门 | 判据 |
|---|---|---|
| 1 | **构建** | `B + pins(S)` 编译出全部 oracle 变体 |
| 2 | **保真** | 每个源文件逐字节等于记录的上游 blob（tier-2 则每个 pin 函数逐字节等价） |
| 3 | **复现** | `pocᵢ` 在切片二进制上开火，指纹匹配 ARVO 参考指纹（行号允许漂移） |
| 4 | **负对照** | 漏洞 i 切到 OFF、其余不变，`pocᵢ` 不开火 |
| 5 | **隔离对照** | `pocᵢ` 在只开漏洞 i 的构建上同样开火；与闸门 3 的差异记为干扰量 |
| 6 | **可区分** | 指纹在切片内唯一，否则按 §同指纹合并为一个 ID |

闸门 4 和 5 由 §4.1 的开关机制免费提供，这是相对原设计最大的成本下降。

**确定性闸门本轮暂缓**，设计见 [determinism.md](determinism.md)，待搬运方法论跑通后再接入。

任何一条不过 → 出局并记录原因。各拒收原因的占比本身是论文结果（"为什么漏洞搬运会失败"）。

## 9. 流水线

| 阶段 | 命令 | 输入 → 输出 |
|---|---|---|
| 窗口实测 | `memvul sweep` | 提交历史 + 全部 PoC → 存活矩阵、每漏洞窗口 |
| 基线选择 | `memvul base` | 窗口集合 → 区间穿刺，选 `B`，报天然产量 |
| pin 求解 | `memvul pin` | 非天然漏洞 → 认领集扩张、vul/fix pin 对 |
| 切片构造 | `memvul slice` | 冲突图 → 最大兼容集，多切片划分 |
| 验证 | `memvul verify` | 六道闸门，产出 `bug.yaml` |
| 物化 | `memvul emit` | pin 表 → 源码树 + manifest + CMake 开关 |

`scripts/sweep_bases.sh` 是 `sweep` 阶段的雏形，已能在 ARVO 容器内跑通。

## 10. 已知局限

| 局限 | 处理 |
|---|---|
| 拼装树是历史上不存在的程序 | §6 量化并公布 `mosaic_ratio` / `temporal_spread`；提供零 pin 的 `pure` 档 |
| 窗口是"可观测性"而非"缺陷存在性" | §7 明确采用操作定义，并说明理由 |
| 单体架构项目冲突率高、密度上限低 | §5 把模块化程度写进选片打分；不强行拉高密度 |
| tier-2 函数级 pin 破坏整文件不变式 | §4.3 单独标记、单独计数、可整体排除 |
| 认领集扩张会改变冲突图 | §3 迭代求解 |
| PoC 只有一个、覆盖窗口内所有形态的假设未验证 | 由闸门 3 的指纹匹配兜住；不匹配即出局 |
